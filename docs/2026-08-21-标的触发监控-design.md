# 标的触发监控 — 设计说明

**日期**：2026-08-21
**状态**：历史设计归档；其运行、工作流与 Pages 入口已由统一“每日监控”取代
**目标**：把研究报告里的**关键价位/触发条件**结构化为机器可读数据源，每日自动拉行情比对"是否进入买入/加仓区间"，并跟踪**事件**（财报日、复检日、公告日），到期主动提醒。

> 当前实现见 `skills/daily-monitor.md`、`tools/daily_monitor.py` 和 `.github/workflows/daily-monitor.yml`：工作日 17:30（Asia/Shanghai）运行，输出价格、正式披露、其他监控三部分。本文以下路径、时间和“监控与周检”组合页描述仅记录首版历史，不再是活动配置。

---

## 1. 问题与目标

现有管理层的痛点：

1. 触发价位散落在 `重点标的看板`（13 家）和 `标的跟踪表`（60 条）的自然语言里，**人肉比对**，一周才看一次，漏触发。
2. 复检日/财报日藏在 60 行台账里，**没人主动提醒** → 8/15 周检一次堆积 5 个 P0（复检窗口已过未闭环）。
3. 价格到了区间，判断"是否建仓"的依据（红线、条件）需要回源报告，但没人把它带出来。

本系统回答三个问题：

1. **价位到了没有？**（每日扫描，比对触发区间）
2. **哪个事件到期/临近？**（财报、复检、公告，自动提醒）
3. **到了之后怎么办？**（每条触发都带"动作"+"备注"，指向 thesis/研究报告的红线）

---

## 2. 方案选择

| 对比项 | 本方案 | 未采用 |
|--------|--------|--------|
| 触发点存储 | `data/triggers.json` 结构化 JSON（机器读） | 解析 markdown 表格（脆弱） |
| 扫描节奏 | 每日运行脚本（手动或 cron） | 实时推送（依赖行情源订阅，复杂） |
| 提醒 | GitHub Actions + Server酱微信推送 + 每日报告文件 | 邮件/Telegram（需配置凭证） |
| 与看板/台账 | 触发点从看板/台账**登记**进 JSON，看板仍是研究层 | 替代看板/台账 |

**原则**：`triggers.json` 是**机器可读的触发层**，研究结论（为什么买、红线在哪）仍在看板/台账/thesis；脚本只负责"价位到没到、事件到没到"，不替人决策。

## 3. 文件与数据模型

### 3.1 文件

| 文件 | 角色 |
|------|------|
| `data/triggers.json` | 唯一数据源：标的、代码、触发区间、事件 |
| `tools/trigger_scanner.py` | 每日扫描脚本（腾讯行情 API，零依赖） |
| `reports/trigger-scan/trigger-scan-{YYYYMMDD}.md` | 每日报告（历史留档） |
| 本文 | 设计说明 |

### 3.2 triggers.json 结构

```json
{
  "schema": 1,
  "updated": "2026-08-21",
  "targets": [
    {
      "id": "腾讯",                        // 唯一 ID
      "name": "腾讯控股",                  // 显示名
      "group": "重点",                     // 重点 / 台账
      "codes": {"H": "hk00700"},           // 市场→腾讯行情代码（A:sh/sz, H:hk, US:us, KR:kr, JP:jp）
      "source": "重点标的看板 2026-08-12",  // 触发点来源
      "links": ["reports/腾讯/腾讯-thesis.md"],
      "zones": [                           // 价位触发区间（可多条，按市场区分）
        {"label": "加仓带", "dir": "range", "low": 400, "high": 430,
         "market": "H", "action": "评估加仓",
         "note": "仅当红线未触或Q3证实FCF转正+AI回收"}
      ],
      "events": [                          // 事件（财报/复检/公告/投资者日）
        {"date": "2026-09-30", "type": "财报", "label": "2026Q3财报",
         "note": "盯Q3 FCF转正、AI预付款回收", "market": "H"}
      ]
    }
  ]
}
```

### 3.3 zone 的 dir 语义

| dir | 含义 | 示例 |
|-----|------|------|
| `below` | 价格 ≤ high 触发（跌破买入线） | `dir:below, high:180` = 跌到 180 以下考虑 |
| `above` | 价格 ≥ low 触发（涨过警示线/不追高线） | 微软 `high:440, dir:above` = 已过不追高线 |
| `range` | low ≤ 价格 ≤ high 触发（进入区间） | `[400,430]` = 进入加仓带 |

**接近判定**：距触发边界 ≤3% 标为"接近"，供提前关注。

### 3.4 事件状态机

| 状态 | 含义 |
|------|------|
| `OVERDUE` | 日期已过 → 🔴 必须处理 |
| `TODAY` | 今天到期 → 🟠 |
| `SOON` | 7 天内到期 → 🟡 |
| `FUTURE` / `OPEN` | 未到期或待定 → 不提醒 |
| `done: true` | 已处理（复检完成/事件落地）→ 不再提醒，保留留档 |

## 4. 维护流程

### 4.1 研究报告产出时（强制）

新报告含明确买卖/观望建议、或明确复检节点时，按以下规则登记 `data/triggers.json`：

1. **价位**：报告给出价格带/触发线 → 在对应标的 `zones` 加一条（label 用报告原词，action 用报告稳健结论，note 写触发附加条件）。
2. **事件**：报告给出复检日/财报日 → 在 `events` 加一条（date 用 YYYY-MM-DD，note 写要核验什么）。
3. 标的不存在 → 新建 target（id 唯一，codes 填市场代码）。
4. 更新 `updated` 字段。

**没有登记 = 该触发点不在监控内。**（与 `标的跟踪表` 的"没有台账行 = 未进入跟踪体系"同一原则）

### 4.2 每日扫描

```bash
python3 tools/trigger_scanner.py            # 扫描 + 写报告
```

**GitHub Actions（推荐，手机必达）**

[`.github/workflows/trigger-scan.yml`](../.github/workflows/trigger-scan.yml) 每个工作日 18:00（cron `0 10 * * 1-5`，10:00 UTC）自动执行：扫描 → 写日报 → **Server酱推送微信** → 日报回写仓库。也可在 Actions 页面手动触发。

1. 注册 Server酱 Turbo（sct.ftqq.com，微信扫码）拿 SendKey；
2. 仓库 `Settings → Secrets and variables → Actions` 添加 Secret：`SERVERCHAN_SENDKEY`；
3. 首次部署后手动 Run workflow 一次验证。推送脚本见 `.github/scripts/notify_serverchan.py`（有触发/事件才推，无则跳过）。

注意：私有仓库定时工作流 **60 天无活动会自动停用**；日报每天回写仓库即视为活动，可自续。cron 不保证整点准时，可能延迟数分钟。

### 4.3 事件处理完（done 标记）

复检完成/财报读完 → 给该事件加 `"done": true`，保留在 JSON 里作留档；若事件演变为新周期事件（如下一季财报），另加新事件。

### 4.4 定期对账（并入周检）

周检时跑一次 `python3 tools/trigger_scanner.py --json`，与看板/台账交叉核对：
- 触发但看板未反应 → 看板更新；
- 报告有明确价位但 JSON 无 → 补登记；
- 事件 OVERDUE 且已处理 → 标 done。

## 5. 边界与原则

- **触发 ≠ 买入信号**：脚本只报"价位到达"，是否建仓以对应 thesis/研究报告的红线与条件为准（note 字段已带出）。
- **行情口径**：腾讯 API 快照，A股/港股当日最新，美股/韩股/日股为最近收盘；批量上限约 30 个/请求，脚本已分批。
- **估值类触发不在此系统**：PE/PS 等估值线（如 MINIMAX PS<10x、Mastercard PE≤25x）依赖财务数据，无法用纯价格比对，仅在 note 中注明，不设 zone。
- **不替代看板/台账/thesis**：JSON 是触发层；研究层文件不变。
- 本系统用于学习研究跟踪，不构成投资建议。

---

## 6. 验收标准

- `python3 tools/trigger_scanner.py` 一次跑通：64 标的行情全量拉取，触发/接近/事件三区正确分类。
- 已触发区能带出"动作 + 备注"，直达 thesis/报告链接。
- 事件按 OVERDUE/TODAY/SOON 提醒，done 标记后消失。
- `--json` 输出可被脚本/周检消费；`--watch` 可定点扫描。
- 报告写入 `reports/trigger-scan/` 并可回看历史。

## 8. 已确认决策摘要

| 决策点 | 结论 |
|--------|------|
| 触发点存储 | `data/triggers.json` 结构化 JSON |
| 行情源 | 腾讯行情 API（零依赖、无需鉴权、多市场） |
| 扫描节奏 | 每日 GitHub Actions 定时（工作日 18:00 CST） |
| 提醒 | Server酱微信推送 + 每日报告文件 |
| 触发判定 | below / above / range + 3% 接近带 |
| 事件 | 财报/复检/公告/投资者日，OVERDUE/TODAY/SOON |
| 与看板/台账 | 触发层分离，研究层不动 |
| Pages 入口 | 周检与触发监控合并为「监控与周检」单一入口（构建时组合，数据层与历史留档保持分离） |
